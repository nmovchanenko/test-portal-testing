## Context

See `proposal.md` - Why for motivation. This is a retroactive design: the artifacts it describes (`.mcp.json`, `.claude/agents/*.md`, `tests/api/seed.spec.ts`, `specs/README.md`) already exist in `playwright-ts/`, generated by Playwright's own first-party tooling rather than hand-written:

```sh
npx playwright init-agents --loop claude
```

This is Playwright's official "Test Agents" feature (shipped in `@playwright/test` 1.56+, confirmed present in the 1.62.1 already pinned in `playwright-ts/package.json`): a planner, generator, and healer subagent definition, plus an MCP server (`playwright run-test-mcp-server`) that exposes the browser-automation and authoring tools they call. Nothing here is bespoke to this repo — the design decisions below are about *how it was scoped and invoked*, not about inventing the agents themselves.

## Goals / Non-Goals

**Goals:**
- Document why the agents live inside `playwright-ts/` rather than at the repo root, and whether that scoping should be the template for future framework directories.
- Record the exact command used, so it's reproducible (re-running it to pick up a newer Playwright agent definition, or bootstrapping the same pattern in a future framework directory).
- Reconcile the `playwright-ts` spec's "zero test cases" requirement with the seed file the init command created.

**Non-Goals:**
- Redesigning or customizing the agent prompts themselves — they're used as Playwright ships them.
- Writing a real test plan or generating real tests — this change specs the scaffolding, not its first output (see proposal.md - Impact).
- Deciding whether other framework directories (`cypress-ts`, etc.) adopt an equivalent pattern — each framework has its own agent/MCP tooling landscape; that's a decision for whenever such a directory is proposed.

## Decisions

### Scoped to `playwright-ts/`, not the repo root
`.mcp.json` and `.claude/agents/` live inside `playwright-ts/`, not at the repo root. This matches `repo-scaffolding`'s "self-contained framework directories" requirement: the agents are Playwright-specific (their tools are literally `mcp__playwright-test__*`), so they have no meaning in a framework directory for a different tool. A root-level `.mcp.json`/`.claude/` would either be empty of framework-specific tooling or would need per-framework conditionals — both worse than one config per directory.
- Alternative considered: root-level agents shared across framework directories — rejected; there's nothing to share yet, and it would violate the self-containment convention `repo-scaffolding` already establishes.

### Keep Playwright's default agent definitions unmodified
The three subagent `.md` files and `.mcp.json` are used exactly as `init-agents` generated them, not hand-edited.
- Alternative considered: trim the generator/healer tool lists or rewrite prompts to match this repo's conventions (e.g. reference `TESTPORTAL_BASE_URL`) — rejected for now; customizing forked prompts drifts from upstream and has to be manually kept in sync with future Playwright releases. If the defaults prove insufficient once real test plans are written, that's its own future change with a concrete problem to justify the fork.

### Test plans in `specs/`, generated tests in `tests/`
The planner's output (test-plan markdown) is kept in `playwright-ts/specs/`, separate from the actual Playwright spec files under `playwright-ts/tests/`. This mirrors the generator agent's own convention (its example references `specs/plan.md` as the plan source for a generated test) and keeps "what to test" documents distinguishable from "the test code" at a glance.
- Alternative considered: put test plans alongside their generated tests in `tests/` — rejected; would mix prose planning documents into a directory whose whole purpose (per the `playwright-ts` spec) is to hold runnable Playwright projects.

### Leave `tests/api/seed.spec.ts` as the generated placeholder
`init-agents` scaffolds one seed file per selected project (here, `api`) with an empty test body and a `// generate code here` comment — no real navigation or setup logic yet. This change keeps it as-is rather than inventing seed logic now.
- Alternative considered: pre-fill the seed with a `page.goto(TESTPORTAL_BASE_URL)` navigation — rejected; the right shared starting state (plain navigation vs. an authenticated session vs. something else) depends on what the first real test plan actually needs, which isn't known yet. Filling it in blind risks the generator building on a wrong assumption. This is exactly the kind of decision the `playwright-test-authoring-agents` spec locates ("a seed file SHALL exist per test-plan group") without dictating its content.

### `specs/README.md` gets real content in this change
The file currently just says "This is a directory for test plans." Since this change is the first place documenting the `specs/` convention, `tasks.md` includes writing a proper README for it (what it's for, how the planner populates it, how it relates to `tests/`) rather than leaving the one-line placeholder — consistent with `repo-scaffolding`'s "minimum README content" bar applied at the sub-directory level.

## Risks / Trade-offs

- **[Risk]** Playwright's Test Agents feature is relatively new (1.56+) and could change shape in future releases (different tool names, different file layout). → **Mitigation**: this change documents the exact `init-agents` command used, so re-running it and diffing is a straightforward way to pick up upstream changes; the spec describes the workflow's role (plan → generate → heal) rather than pinning exact tool names, so it stays valid even if Playwright renames individual MCP tools.
- **[Risk]** An empty seed file means the `api` project's first generated tests could all inherit a missing/wrong starting state if someone writes a plan before filling in the seed. → **Mitigation**: accepted for now (see Decisions); flagged here so it's a known gap, not a silent one, and becomes a fast follow the first time a real plan needs it.
- **[Risk]** Because the healer agent's instructions permit marking a stubborn failure `test.fixme()`, an unattended run of the agent could silently accumulate skipped tests. → **Mitigation**: this is Playwright's default behavior and out of scope to change here; worth revisiting once the team has real experience with the healer agent in this repo.

## Migration Plan

Retroactive documentation of existing files, no code migration needed:
1. Confirm the existing `.mcp.json`, `.claude/agents/*.md`, and `tests/api/seed.spec.ts` match what `npx playwright init-agents --loop claude` produces (no drift to reconcile).
2. Replace `specs/README.md`'s placeholder with real content per the Decisions section.
3. Update `playwright-ts/README.md`'s "what this covers today" section to mention the authoring-agent workflow.
